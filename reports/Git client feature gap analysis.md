# Chrono should win on trust, not features

Chrono already covers most of the core feature set of GitKraken Desktop 12.7 (Nov 2026): commit graph, WIP node, drag-and-drop merge and rebase, hunk staging, interactive rebase with `--update-refs`, three-way conflicts, worktrees, a terminal, a command palette and undo. Its remaining gaps fall into three groups. **Safety features**: signature badges, hook output, conflict prediction before an operation, merged-branch cleanup. **Branch relationships**: stacked branches with a parent model, and fork-point dimming. **Hosting write actions**: creating PRs and viewing or re-running CI checks. These matter because users choose Git clients mostly for **speed, stability, line/hunk staging, keyboard flow and fair pricing without a login wall**. They rarely mention AI or cloud collaboration as a reason to switch ([HN 45878578](https://news.ycombinator.com/item?id=45878578); [AlternativeTo GitKraken reviews](https://alternativeto.net/software/gitkraken/reviews/)). GitKraken's 2026 work centers on paid cloud and agent features: Launchpad, Cloud Patches, Team View, credit-metered AI, and PR review moved to the web ([GitKraken pricing](https://www.gitkraken.com/pricing); [GitKraken 12.x release notes](https://help.gitkraken.com/gitkraken-desktop/current/)). That leaves room for a free, login-free, Linux-capable client built on the git CLI, which Chrono already is. The best first moves are cheap ones that build trust: signing badges, a performance preset, typed search, hook streaming, co-author trailers and templates, issue autolinks and fork-point dimming. Conflict prediction, stacked branches, branch cleanup and PR creation come next. Agent-session orchestration is a strategic bet; ship it only after the core is solid.

## Every leading client now ships the same 2026 core

By late 2026 the market leaders have converged on one baseline. **Worktree support is now standard**: Tower 12.5, Fork 2.41+, SmartGit 25.1, Sublime Merge build 2130, GitHub Desktop 3.6 and GitKraken 10.5 all have it ([Tower 12 notes](https://www.git-tower.com/release-notes?os=mac&version=12); [Fork Mac notes](https://git-fork.com/releasenotes); [SmartGit What's New](https://www.smartgit.dev/whats-new/); [Sublime Merge changelog](https://www.sublimemerge.com/download); [GitHub changelog 3.6](https://github.blog/changelog/2026-06-26-github-desktop-3-6-worktrees-and-deeper-copilot-integration/)). AI commit messages are also standard. GitHub Desktop has had them since 2025, and in 3.6 it added bring-your-own-key and **locally running models** ([GitHub changelog 3.6](https://github.blog/changelog/2026-06-26-github-desktop-3-6-worktrees-and-deeper-copilot-integration/)). Tower, Fork and SmartGit all call **locally installed agent CLIs (Claude Code, Codex, Cursor)** rather than bundling a hosted model ([Tower 16 notes](https://www.git-tower.com/release-notes?os=mac&version=16); [Fork Mac notes](https://git-fork.com/releasenotes); [SmartGit What's New](https://www.smartgit.dev/whats-new/)). Chrono's local Ollama/offline-rules commit draft is in line with this.

GitKraken still has the broadest single feature set. Beyond what Chrono already has, it offers:

- profiles, plus GPG and SSH signing with a verification badge;
- hooks with a custom path and a skip option;
- an LFS UI;
- a built-in Gitflow;
- shallow clone and sparse checkout;
- multi-commit cherry-pick with reorder, squash and drop;
- combined diffs for consecutive commits;
- restoring a file from any commit;
- solo, hide and pin of branches, and Smart Branch Filtering;
- a 3-way Monaco merge editor;
- AI explain, compose and conflict resolution.

([GitKraken commit signing](https://help.gitkraken.com/gitkraken-desktop/commit-signing-with-gpg/); [GitKraken hooks](https://help.gitkraken.com/gitkraken-desktop/githooks/); [Gitflow](https://help.gitkraken.com/gitkraken-desktop/git-flow/); [GitKraken 11.x notes](https://help.gitkraken.com/gitkraken-desktop/11x/); [GitKraken AI](https://help.gitkraken.com/gitkraken-desktop/gkd-gitkraken-ai/)).

Its direction since 12.0 has been an "agent workspace". There is an Agent Sessions view with worktree cards, **multiple WIP nodes in the graph (one per worktree)**, multi-tab terminals, and permission prompts for Claude Code, Codex and Copilot CLI. PR *review* moved out of the desktop app to gitkraken.dev in 12.3 ([GitKraken 12.x notes](https://help.gitkraken.com/gitkraken-desktop/current/)). In 12.7.0 GitKraken also **finished migrating to the git executable** after years of running on a built-in library ([GitKraken 12.x notes](https://help.gitkraken.com/gitkraken-desktop/current/)). That validates Chrono's shell-out architecture.

## Users reward speed, staging and control, not cloud or AI

The user evidence is thinner than the feature evidence, and that limits how precisely features can be ranked. Major surveys no longer break out Git GUI clients. The newest direct data (Stack Overflow 2022) shows **84.6% of professionals use the command line** for version control and 54.4% a code editor ([i-programmer summary](https://i-programmer.info/news/99-professional/15589-shifts-a-stability-in-developer-landscape.html)). Reddit was not accessible to the research. Sentiment therefore comes mainly from Hacker News, AlternativeTo and G2, and the mention counts are directional, not statistical.

Within those limits the pattern holds across sources. The Nov 2025 HN lazygit thread (436 points, 222 comments) is the clearest signal. Users praised **line-level staging and custom patch building as "easily the best feature"**, and clients known for speed and a clean UI got the warmest comments: Fork, Sublime Merge, magit and lazygit ([HN 45878578](https://news.ycombinator.com/item?id=45878578); [HN 45880203](https://news.ycombinator.com/item?id=45880203)). The reasons people switch away are just as consistent:

- **Slowness and instability**, with SourceTree the most-named client people left.
- **Moves to subscriptions**, at Tower and SmartGit.
- **GitKraken's login requirement and paywalled private repos.** AlternativeTo rates it 3.1/5 and cites "high ram usage, cpu usage, and a slow interface".
- **No Linux build** for Fork, Tower or SourceTree.

([HN 45880203](https://news.ycombinator.com/item?id=45880203); [AlternativeTo](https://alternativeto.net/software/gitkraken/reviews/); [Hostinger](https://hostinger.com/tutorials/?p=18077)). One GitKraken user said "I just don't feel in control of what I'm trying to achieve with Git" ([HN 45880203](https://news.ycombinator.com/item?id=45880203)). Chrono's git command log and deep links speak directly to that complaint.

AI gets a cautious reception. GitHub's own docs say commit generation "might struggle with intricate code changes" ([GitHub Docs](https://docs.github.com/en/enterprise-cloud@latest/copilot/responsible-use/copilot-in-github-desktop)). Research finds LLM messages degrade without context and should be reviewed by a human ([arXiv 2404.14824](https://arxiv.org/html/2404.14824v2)). Stack Overflow's 2025 survey reports trust in AI "at an all time low" ([Stack Overflow](https://stackoverflow.co/company/press/archive/stack-overflow-2025-developer-survey/)). No HN commenter named AI as a reason to pick a client. **AI is table stakes, not a differentiator.** Chrono should make its existing draft feature better (more context, opt-in, local) rather than widen its AI surface.

The newest expectation comes from tools outside the classic GUI category. Jujutsu was the **most-mentioned tool in the lazygit thread (~15 mentions)**, praised for an operation log where `jj op undo` can undo *any* past operation ([HN 45878578](https://news.ycombinator.com/item?id=45878578); [jj operation-log docs](https://sources.debian.org/src/jujutsu/0.30.0-1/docs/operation-log.md)). GitButler is admired for stacks and its "escape hatch" op log. It is also criticized as "not ready for the real world" because of how it handles merge conflicts ([HN 46767534](https://news.ycombinator.com/item?id=46767534)). By comparison, GitKraken's undo covers **only the most recent action** ([GitKraken undo](https://help.gitkraken.com/gitkraken-desktop/undo-and-redo/)), while Tower's Cmd+Z covers staging, commits, branches, rebases and stashes ([Tower Undo](https://www.git-tower.com/features/undo)). Chrono's persisted undo/redo journal already sits in jj territory. Each new operation in the roadmap should write to that journal, including restack, branch archive and PR checkout. That would make "undo anything" a defensible claim.

Accessibility is unclaimed ground. No accessibility conformance statement was found for GitKraken, Fork, Tower, SourceTree or Sublime Merge. A blind developer built his own GitHub tool because mainstream ones were not screen-reader friendly ([AppleVis](https://applevis.com/forum/windows/github-assistant-accessible-way-use-github-screenreader)). GitHub Desktop's report claims full WCAG 2.2 AA support, but earlier revisions of the same report contradict it ([GitHub ACR](https://accessibility.github.com/conformance/desktop-github-com)).

## Chrono's gaps cluster around safety, branch relationships and hosting writes

Compared with the combined feature set above, Chrono is missing the following. A quick scan of the source found no signing, Gitflow, co-author, commit-template, custom-command, image-diff or PR-creation code. Search already supports message, author, path and `-G` change filters. Maintenance runs only on demand (`git maintenance run`). Sparse checkout supports `set --cone` and `disable`. Commits accept `--no-verify` and `--signoff`.

**Trust and safety.** These are the most-cited themes in user feedback, and Chrono has gaps in each:

- No **signature verification badges** or signing setup (GitKraken, Fork, Tower).
- No **streamed hook output** with a deliberate bypass after a failure (GitHub Desktop 3.5.5, GitKraken).
- No **conflict prediction** before an operation (Fork, GitKraken).
- No **merged/stale branch detection** that recognizes squash merges (Tower 17, GitLens 19.6).

**Branch relationships.** Chrono's rebase planner can already pass `--update-refs`. But it has no record of which branch is stacked on which, so it cannot restack a chain, dim commits before a fork point, or default a PR's base branch the way Tower and GitLens can.

**Hosting writes.** Chrono's PR triage is read-only. GitKraken, GitHub Desktop, SmartGit and GitLens all create PRs, show CI status, and either re-run checks or notify about them.

A long tail of smaller conveniences is also missing:

- typed search operators;
- co-author trailers and commit templates;
- issue autolinks;
- image diffs;
- ahead/behind counts on the sync buttons;
- word-wrap and ignore-whitespace toggles;
- identity profiles;
- user-defined custom commands.

## Prioritized roadmap

Each tier is ordered by user value relative to effort. "User evidence" separates direct user signal from vendor adoption; adoption is weaker evidence. The implementation notes assume Chrono's Node backend calls `git` through argv arrays, with no shell string interpolation. That matters: **SourceTree 3.4.33 patched command execution through Git-flow branch names and a `sourcetree://` handler** ([SourceTree 3.4.33 notes](https://product-downloads.atlassian.com/software/sourcetree/windows/ga/ReleaseNotes_3.4.33.html)), and Chrono has both deep links and an explorer shell menu. Commands marked *(standard git)* are not from the research notes. Check them against the installed git version before relying on them.

### Tier 3: strategic bets and larger builds

| Feature | Who has it | User evidence | Implementation notes |
|---|---|---|---|
| **Agent sessions per worktree** (multiple WIP nodes, launch an agent CLI in a worktree terminal, review agent diff) | GitKraken 12.x, SmartGit 26.2 RC, GitHub Desktop 3.6 (worktrees pitched for agents), GitLens 19.x, Tower 18 (`gittower status` to review agent work), Fork (Claude/Codex/Cursor review) | Strong vendor convergence; no direct user-preference evidence found | Chrono already has worktrees, a terminal and multi-repo tabs. | **Graph scale-out**: paging and lazy decorations | GitKraken (Initial Commits ≥500, lazy load) | Direct: speed. Avoid `A..B` topo queries for the main view ([GitHub Blog](https://github.blog/open-source/git/gits-database-internals-ii-commit-history-queries/)). Defer `--stat`, `%G?` and file lists for huge commits until a row is selected. |
| **AI beyond commit drafts**: explain commit/branch, PR description, stash message, conflict explanation, commit split | GitKraken AI (explain, compose, conflict preview), GitHub Desktop 3.6 (conflict suggestions), GitLens (changelog) | Weak or negative user signal ([DEV](https://dev.to/hopkins_jesse_cdb68cfa22c/i-let-ai-write-my-git-commits-for-30-days-the-data-was-messy-38bi); [Stack Overflow 2025](https://stackoverflow.co/company/press/archive/stack-overflow-2025-developer-survey/)) | Cheap to add because Ollama is already wired up. Keep it opt-in and local-first, always editable, and route every rewrite through the undo journal. Prioritize **context** (branch name, issue ID, diff stat) over new entry points. |
| **Sparse-checkout and partial-clone UX** | GitKraken 11.6–12.0 (shallow and sparse in the clone dialog), Sublime (partial clone), Scalar | Monorepo users | Chrono already has `set --cone` and `disable`. Add `add`, `list`, `reapply` (after merges), `clean --dry-run` and `check-rules -z` for an "outside cone" indicator ([git-sparse-checkout](https://git-scm.com/docs/git-sparse-checkout)). Add clone options `--depth`, `--filter=blob:none`, `--sparse` *(standard git)*. |
| **Git notes**, **activity treemap/visual history**, **CI/review OS notifications** | SmartGit 25.1 (notes), Fork 2.52 (treemap), GitLens (Visual History), GitHub Desktop (notifications) | Niche | Notes: `git notes --ref=<ns> show/add` plus `%N` in the log *(standard git)*. Notifications: Electron `Notification` driven by provider polling. |

Some features are deliberately left off. Cloud Patches, Team View, org-wide Conflict Prevention and Insights all need a vendor cloud, and the account wall around such features is what users complain about ([AlternativeTo](https://alternativeto.net/software/gitkraken/reviews/)). Mercurial and SVN bridges serve shrinking audiences. Custom JSON themes are a weak signal: GitKraken *removed* them in 11.8 ([GitKraken 11.x](https://help.gitkraken.com/gitkraken-desktop/11x/)).

## Conclusion

The competitive question for Chrono is no longer feature count. GitKraken just finished moving onto the same git-CLI foundation Chrono started with, and every major client now ships worktrees and AI messages. What separates clients in 2026 is trust and control: whether a client can say what an operation will do before running it (conflict prediction, a command log, previews), undo any operation afterward (an op log, not single-step undo), and show whether history is authentic and up to date (signature badges, merged-branch detection, CI state). Chrono's persisted undo journal and visible command log already provide most of this, which GitKraken's design does not. Tiers 1 and 2 mostly extend those strengths.

The main uncertainty is the user evidence. It comes from enthusiast forums, review sites and vendor behavior rather than surveys, and Reddit could not be checked. Agent-session features in particular have universal vendor adoption but no measured user demand. Run them as an inexpensive experiment on top of the existing worktree and terminal code, and invest in proportion to what Chrono's own users do with them.
